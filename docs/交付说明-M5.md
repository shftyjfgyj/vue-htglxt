# 交付说明 · M5（评论楼中楼 / 通知中心 / 批量操作 / Excel 导入导出 / 全文检索）

## 1. 交付内容

| 能力 | 后端 | 前端 |
| --- | --- | --- |
| 评论楼中楼 | `comments.parent_id` 校验（父评论必须同文章）、`GET /api/v1/articles/:id/comments` 返回评论树 | 阅读页 `ArticleReaderView.vue` + 递归组件 `CommentNode.vue`，支持任意层级回复 |

## 2. 关键设计

- **通知不阻塞业务**：`notify()` 内部 try/catch，只记日志；自己评论自己的文章不产生通知；通知按用户强隔离（只能查/改自己的）。
- **批量操作不是事务整体回滚**：逐条在事务内执行并记录错误，返回 `{requested, affected, skipped, errors[]}`，前端提示「成功 N 条、跳过 M 条 + 首个原因」。
- **导入健壮性**：标题去重（同名跳过）、缺标题/正文跳过、分类与标签不存在时自动创建、正文纯文本自动包 `<p>`、状态列支持「草稿/待审核」；工作表缺少必需列时直接 400。
- **上传安全**：导入走独立的内存存储 multer（≤5MB、仅 .xlsx/.csv），与图片上传白名单互不影响。
- **检索降级**：MySQL 5.7 默认分词器对中文无效，故用 `WITH PARSER ngram` 建索引；无索引或短词场景仍可用 LIKE 模式。

## 4. 已知取舍

- 导出上限 5000 条（避免一次生成过大 xlsx）；需要更大规模时应改造为异步导出任务。
- Excel 导入为同步解析，适合千行级；更大量级建议改成队列 + 进度查询。
- ngram 索引会增大写入开销与索引体积，属于中文检索的常见取舍。
