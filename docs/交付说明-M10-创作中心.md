# 交付说明 · M10 创作中心（我的文章）

> 参考掘金创作中心 / CSDN 内容管理 / 知乎创作中心的做法，为作者提供一个「只管自己的文章」的独立页面。

## 1. 页面：我的文章 `/content/my-articles`

菜单挂在「内容管理」下（EditPen 图标）。与原「文章管理」的区别：**只展示当前登录用户自己的文章**，围绕创作流程组织信息。

### 1.1 数据概览（四张卡）

| 卡片 | 内容 |
| --- | --- |
| 全部文章 | 总数 + 回收站篇数 |
| 已发布 | 数量 + 累计浏览 |
| 草稿 | 数量 + 待审核篇数 |
| 互动数据 | 累计点赞 + 收藏 / 评论 |

数据来自新接口 `GET /api/v1/articles/mine/stats`（一次聚合查询，含各状态计数、互动汇总与回收站数量）。

### 1.2 状态分栏

`全部 / 草稿 / 待审核 / 已发布 / 已驳回 / 已下线`，每个分栏带实时数量，点击即筛选。

### 1.3 列表与操作

- 列表：标题 + 分类/标签、状态标签、数据（浏览·赞 / 收藏·评论）、更新时间；**被驳回的文章直接在标题下显示驳回原因**（列表接口新增 `auditRemark` 字段）
- 行内操作：继续编辑 / 编辑、预览、更多（提交审核、发布、下线、**复制为新草稿**、删除）
- 批量操作：勾选后批量提交审核 / 发布 / 下线 / 删除
- 筛选：关键词、分类、**排序（更新时间 / 创建时间 / 浏览量 / 点赞数）**、重置；筛选条件同样有记忆（sessionStorage）
- 导出：一键导出当前筛选结果 Excel；顶部「写文章」直达编辑器

## 2. 新增能力

| 能力 | 说明 |
| --- | --- |
| 复制为新草稿 | `POST /api/v1/articles/:id/duplicate`：标题追加「（副本）」，连同标签一起复制，状态为草稿、不复制互动数据与历史版本；复制后直接进入编辑页 |
| 回收站 | 列表支持 `trashed=true`，只看已软删除的文章；顶部「回收站 N」按钮切换并显示数量 |
| 恢复 | `POST /api/v1/articles/:id/restore`：从回收站恢复到**草稿**状态 |
| 我的统计 | `GET /api/v1/articles/mine/stats` |
| 排序 | 列表接口新增 `sortBy=updated\|created\|views\|likes` |
| 审核意见 | 列表接口返回 `auditRemark`，驳回原因直接可见 |

权限：所有接口都以「本人数据」为边界（`onlyMine` + 服务层校验 `user_id`），内容管理员在「文章管理」里仍可管理全站文章。

迁移文件：`apps/server/sql/006_m10.sql`（幂等，新增菜单 id=17）。

## 4. 过程中修掉的问题

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 服务端编译报 `Cannot redeclare block-scoped variable 'restore'` | 控制器里已有版本恢复的 `restore` | 新的回收站恢复改名 `restoreFromRecycle` |
| 2 | 批量操作提示读不到字段 | 前端按 `result.success/failed` 取值，实际类型是 `BatchResult{affected, skipped}` | 按真实类型修正提示文案 |
| 3 | E2E 断言「（副本）」行数失败 | 早期接口测试遗留的同名文章干扰匹配 | 用例改为自带唯一标题（时间戳），并在结束时清理；同时清理了遗留数据 |
| 4 | 概览文案命中两处（strict mode） | `互动数据` 同时出现在统计卡与页面副标题 | 断言限定到 `.stat-label` |
