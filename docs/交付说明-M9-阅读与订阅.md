# 交付说明 · M9 阅读与订阅（阅读历史 / 关注动态 / 收藏分组）

## 1. 阅读历史与「最近在看」

| 层 | 内容 |
| --- | --- |
| 数据库 | 新增 `article_view_logs`：唯一键 `(article_id, user_id)` + 索引 `(user_id, viewed_at)` |
| 后端 | 阅读详情时 `INSERT ... ON DUPLICATE KEY UPDATE viewed_at = NOW()`——**每人每篇只保留最近一次**，反复阅读不会刷屏；`GET /api/v1/me/history` 返回分页历史 |
| 前端 | 「我的内容库」新增第三个标签页 **最近在看**，列表时间列自动切换为「最近阅读」 |

## 2. 关注动态（作者订阅）

- 复用已有 `follows` 关系：`GET /api/v1/me/feed` 返回**我关注的作者所发布的已发布文章**，按 `publish_at` 倒序。
- 新增页面 **关注动态**（`/content/feed`，菜单在「内容管理」分组下，Bell 图标）：头像 + 标题 + 摘要 + 作者/分类/发布时间 + 浏览/赞/评论 + 标签，点击进入阅读页；未关注任何人时给出去「关注管理」的引导按钮。

## 3. 收藏分组

- 数据库：`article_favorites.folder`（默认 `默认分组`）。
- 后端：收藏时可指定分组（`POST /articles/:id/favorite { folder }`，重复收藏会更新分组）；`GET /me/favorite-folders` 返回分组及数量；`PUT /me/favorites/:articleId/folder` 移动分组；`GET /me/favorites?folder=` 按分组筛选。
- 前端：内容库收藏页出现**分组筛选药丸**（全部 / 各分组 + 数量），每行显示所属分组并提供「移动分组」（下拉可选已有分组或新建）。空分组会自动从筛选条消失。

## 4. 接口清单（新增）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/me/history?page&pageSize` | 最近在看（阅读历史） |
| GET | `/api/v1/me/feed?page&pageSize` | 关注动态（我关注的作者的文章） |
| GET | `/api/v1/me/favorite-folders` | 我的收藏分组及数量 |
| PUT | `/api/v1/me/favorites/:articleId/folder` | 移动收藏分组 |
| GET | `/api/v1/me/favorites?folder=` | 按分组筛选收藏（原有接口扩展） |

迁移文件：`apps/server/sql/005_m9.sql`（幂等；含 `article_view_logs` 建表、`folder` 列存在性判断、关注动态菜单）。

## 6. 过程中修掉的问题

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | `GET /me/history` 返回 500 | 通用列表查询里我写成了别名 `l.viewed_at`，实际别名是 `rel` | 改为 `rel.viewed_at` |
| 2 | E2E 收藏点击无效 | 文章详情未加载完就判断了按钮状态 | 先等标题出现、再用 `locator.or()` 等按钮渲染 |
| 3 | 移动分组弹窗点不到确定 | `el-select` 的 `allow-create` 下拉浮层遮住了按钮 | 测试改为选择已有分组（并先用接口确保分组存在） |
| 4 | 断言「学习资料」分组筛选条失败 | 分组内收藏被移走后，空分组会从筛选条消失（预期行为） | 断言改为移动后应出现的「默认分组」 |
