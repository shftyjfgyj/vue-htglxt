# 部署手册（M6）

> 第一次部署、需要「Docker / nginx 怎么下载安装」的完整过程，请看 **[部署-从零开始.md](./部署-从零开始.md)**（含本机实测记录与排错对照表）。
> 本文偏向配置清单与运维命令速查。

## 1. 两种部署方式

| 方式 | 适用 | 入口文件 |
| --- | --- | --- |
| Docker Compose | 推荐，环境一致性最好 | `docker/docker-compose.yml` |
| 宿主机 + PM2 + nginx | 无 Docker 的服务器 | `docker/ecosystem.config.cjs` + `docker/nginx-host.conf` |

两种方式的产物结构一致：**nginx 托管前端 dist** + **反向代理 /api 与 /uploads 到 API:3001**。

## 2. Docker 部署

```bash
cd docker
cp .env.example .env        # 若无该文件，按下方“环境变量”自行创建
# 必填：两个 JWT 密钥（生产校验，缺省会拒绝启动）
#   JWT_ACCESS_SECRET / JWT_REFRESH_SECRET（长度 >= 16，且不能以 dev- 开头）
docker compose up -d --build

# 首次部署执行数据库迁移 + 种子（挂 tools profile，跑完即退出）
docker compose --profile tools run --rm migrate
```

访问：`http://<服务器>:8080`（web 容器 nginx）→ API 通过容器内网 `api:3001` 代理。

服务清单：mysql（含 healthcheck）→ api（依赖 mysql 健康）→ web；上传目录用命名卷 `upload-data` 持久化。

> 注意：`apps/web/nginx.conf` 使用 `resolver 127.0.0.11` + `set $api_upstream` 做**延迟解析**。若改回 `proxy_pass http://api:3001;`，nginx 会在加载配置时解析容器名，`api` 未就绪就会启动失败（`nginx: [emerg] host not found in upstream "api"`）。

## 3. 非容器部署（PM2 + nginx）

```bash
# 1) 构建
npm run setup
npm run build                       # 后端 tsc + 前端 vite build

# 2) 配置后端环境变量
cp apps/server/.env.example apps/server/.env   # 修改数据库与 JWT 密钥

# 3) 初始化数据库（幂等；--fresh 会清库重来）
node apps/server/dist/db/migrate.js

# 4) 启动后端
npx pm2 start docker/ecosystem.config.cjs     # 或 npm --prefix apps/server start
npx pm2 save && npx pm2 startup               # 开机自启

# 5) 前端交给 nginx
#    把 apps/web/dist 拷到 nginx root，或直接把 root 指向该目录
#    并启用 docker/nginx-host.conf（改 proxy_pass 与 server_name）
nginx -t && nginx -s reload
```

## 4. 环境变量（apps/server/.env）

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| NODE_ENV | 是 | production 时会校验 JWT 密钥不是默认值 |
| PORT | 否 | 默认 3001 |
| DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_DATABASE | 是 | 新库默认 htglxt_v2 |
| JWT_ACCESS_SECRET / JWT_REFRESH_SECRET | 是 | 长度 >= 16，生产环境禁止 dev- 前缀 |
| ACCESS_TOKEN_TTL / REFRESH_TOKEN_TTL | 否 | 默认 15m / 7d |
| CORS_ORIGIN | 是 | 前端访问源，多个用逗号分隔 |
| LOGIN_RATE_LIMIT | 否 | 登录限流阈值（10 分钟窗口），默认 20 |
| SLOW_REQUEST_MS | 否 | 慢请求告警阈值，默认 1000ms |
| METRICS_TOKEN | 否 | 设置后 /metrics 需带 x-metrics-token |
| PDF_FONT_PATH / PDF_FONT_FAMILY | 否 | PDF 报表中文字体（不设则自动查找 simhei.ttf / msyh.ttc / Noto CJK） |
| LOG_LEVEL | 否 | pino 日志级别，默认 info |
| SEED_ADMIN_PASSWORD | 否 | 迁移时创建 admin 账号的初始密码 |

## 5. 备份与恢复

```bash
# 备份（自动读取 apps/server/.env，保留最近 14 份，可用任务计划程序定时执行）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/backup-db.ps1
#   可选参数：-Database htglxt_v2 -OutDir backups -Keep 14 -Mysqldump <完整路径>

# 恢复
mysql -h127.0.0.1 -uroot -p htglxt_v2 < backups/htglxt_v2-YYYYmmdd-HHMMSS.sql
```

Linux 服务器等价命令：mysqldump --single-transaction --routines --triggers htglxt_v2 | gzip > backup.sql.gz，配合 crontab。

## 6. 上线检查清单

1. .env 中 JWT 密钥、数据库密码已替换，METRICS_TOKEN 已设置。
2. npm --prefix apps/server run typecheck && npm test、npm --prefix apps/web run typecheck 通过。
3. node scripts/smoke-*.mjs 在预发环境全绿（或至少跑 M2 与 M3）。
4. 迁移脚本已执行；scripts/db-report.mjs 确认表与索引齐全。
5. nginx 已屏蔽 /metrics 与 /docs（配置里默认 deny）。
6. 备份任务已挂上，且做过一次真实恢复演练。
7. 首次登录后立即修改 admin 初始密码。

## 7. 回滚

- 代码：保留上一版本 dist 目录或用镜像 tag，切换后 pm2 reload / docker compose up -d。
- 数据库：迁移脚本只做新增（不加破坏性变更），回滚代码即可；如必须回滚数据，用最近一次备份恢复。
