# 从零开始部署（含 Docker / nginx 安装全过程）

> 本文面向「第一次在这台机器上部署」的场景，命令可直接复制。
> 文末第 6 节是本机实测记录（nginx 1.28.0 真机跑通），第 7 节是排错对照表。

## 0. 先选路线

| 路线 | 需要装什么 | 适合 | 复杂度 |
| --- | --- | --- | --- |
| **A. 全容器** | Docker Desktop（Windows）/ Docker Engine（Linux） | 正式服务器、要环境一致、以后要扩展 | 低（装完一条命令起） |
| **B. Windows 原生** | Node.js + nginx（Windows 压缩包） | 内网 Windows 机器、不想装 Docker | 中 |
| **C. Linux 原生** | Node.js + PM2 + nginx | 云服务器（CentOS/Ubuntu） | 中 |

三条路线跑的是**同一份代码**：nginx 托管前端 dist，并把 `/api`、`/uploads` 反代到 Node 服务的 3001 端口。

## 1. 安装 Docker（Windows：Docker Desktop）

### 1.1 前置条件（必须满足，否则装完起不来）

1. Windows 10 22H2 及以上（家庭版/专业版都行）或 Windows 11，64 位。
2. CPU 虚拟化已在 BIOS 打开：任务管理器 → 性能 → CPU → 右下角「虚拟化：已启用」。
3. 建议启用 WSL2（Docker Desktop 默认后端）：以管理员身份打开 PowerShell 执行

```powershell
wsl --install              # 安装 WSL2 与默认 Linux 发行版，需要重启
wsl --set-default-version 2
wsl --status               # 确认默认版本为 2
```

### 1.2 下载与安装

- 官方下载页：https://www.docker.com/products/docker-desktop/
- 直链（Windows x64）：https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe

命令行下载（可复制）：

```powershell
$url = 'https://desktop.docker.com/win/main/amd64/Docker Desktop Installer.exe'
Invoke-WebRequest -Uri $url -OutFile "$env:USERPROFILE\Downloads\DockerDesktopInstaller.exe"
# 静默安装（必须管理员权限）
Start-Process -FilePath "$env:USERPROFILE\Downloads\DockerDesktopInstaller.exe" -Wait -ArgumentList 'install','--accept-license','--backend=wsl-2'
```

安装完成后**注销/重启**，启动 Docker Desktop，等左下角鲸鱼图标变成绿色（Engine running）。

### 1.3 国内网络：配置镜像加速（重要）

Docker Hub 在国内经常拉不动，装完先配镜像源：Docker Desktop → 右上角齿轮 **Settings** → **Docker Engine**，把 JSON 改成：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://mirror.ccs.tencentyun.com"
  ],
  "builder": { "gc": { "defaultKeepStorage": "20GB", "enabled": true } },
  "experimental": false
}
```

点 **Apply & restart**。

### 1.4 验证

```powershell
docker version           # 能看到 Client 与 Server 两段
docker run --rm hello-world
docker compose version   # ≥ v2（本项目用 docker compose 子命令）
```

### 1.5 Linux 服务器安装 Docker Engine

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER      # 免 sudo，重新登录生效

# CentOS / Rocky
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker

# 国内镜像加速
sudo mkdir -p /etc/docker && sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{ "registry-mirrors": ["https://docker.m.daocloud.io", "https://mirror.ccs.tencentyun.com"] }
EOF
sudo systemctl restart docker
docker run --rm hello-world
```

## 2. 用 Docker 部署本项目（路线 A）

### 2.1 准备

```bash
git clone <你的仓库地址> vue-htglxt && cd vue-htglxt/docker
# 若没有 docker/.env 就新建一个（compose 会读取同目录 .env）
```

`docker/.env`（**生产必填的两个密钥不能省**，否则 api 容器会拒绝启动）：

```ini
MYSQL_ROOT_PASSWORD=换成强密码
JWT_ACCESS_SECRET=至少16位随机串A
JWT_REFRESH_SECRET=至少16位随机串B
CORS_ORIGIN=http://你的服务器IP:8080
WEB_PORT=8080
API_PORT=3001
METRICS_TOKEN=换个随机串
```

生成随机密钥（Linux/macOS：`openssl rand -hex 32`；Windows：`-join ((1..32) | %{ '{0:x}' -f (Get-Random -Max 16) })`）。

### 2.2 起服务

```bash
docker compose up -d --build          # 构建并后台启动 mysql + api + web
docker compose ps                     # 三个容器都应是 running/healthy
```

### 2.3 初始化数据库（首次必须执行一次）

```bash
docker compose --profile tools run --rm migrate
# 输出出现「数据库迁移完成」即成功；重复执行也安全（幂等）
```

### 2.4 验证

```bash
curl http://127.0.0.1:3001/health          # 直连 API：{"code":0,...,"db":"up"}
curl -I http://127.0.0.1:8080/             # 前端：HTTP/1.1 200
curl -X POST http://127.0.0.1:8080/api/v1/auth/login \
     -H 'Content-Type: application/json' \
     -d '{"username":"admin","password":"Admin@123456"}'
```

浏览器打开 `http://服务器IP:8080`，用 admin 登录；**登录后立刻在「个人中心」改密码**。

### 2.5 日常运维命令

```bash
docker compose logs -f api          # 看后端日志
docker compose restart api          # 重启后端
docker compose down                 # 停止（数据在卷里，不会丢）
docker compose pull && docker compose up -d --build   # 更新版本
docker compose exec mysql mysql -uroot -p htglxt_v2     # 进数据库
docker compose cp api:/app/uploads ./uploads-backup     # 备份上传文件
```

## 3. 安装 nginx（Windows 压缩包方式，5 分钟）

> Windows 版 nginx 是绿色压缩包，解压即用，不写注册表、不需要管理员权限。
> 本仓库已经把 1.28.0 下好放在 `.tmp-nginx\nginx-1.28.0\`，可以直接跳到 3.3。

```powershell
# 3.1 下载
$dir = 'C:\nginx'
New-Item -ItemType Directory -Force -Path $dir | Out-Null
Invoke-WebRequest -Uri 'https://nginx.org/download/nginx-1.28.0.zip' -OutFile "$dir\nginx.zip" -UseBasicParsing

# 3.2 解压（得到 C:\nginx\nginx-1.28.0）
Expand-Archive -Path "$dir\nginx.zip" -DestinationPath $dir -Force

# 3.3 试运行：启动 / 查看 / 停止
$root = "$dir\nginx-1.28.0"
Start-Process -FilePath "$root\nginx.exe" -WorkingDirectory $root -WindowStyle Hidden
Invoke-WebRequest 'http://127.0.0.1' -UseBasicParsing | Select-Object StatusCode   # 默认欢迎页
& "$root\nginx.exe" -s stop

# 3.4 改配置后先校验再热加载（关键习惯，避免改坏导致无法启动）
& "$root\nginx.exe" -p $root -c conf/nginx.conf -t    # 出现 syntax is ok / test is successful 才算过
& "$root\nginx.exe" -p $root -c conf/nginx.conf -s reload
```

把本项目配置放进去：

```powershell
# 用仓库里的宿主机示例配置（内含 SPA 回退 + /api 反代）
# 把 <仓库路径> 换成你本机克隆本项目的位置
Copy-Item '<仓库路径>\docker\nginx-host.conf' "$root\conf\htglxt.conf"
# 编辑它：改 server_name、root 指向前端 dist、确认 proxy_pass 为 127.0.0.1:3001
# 然后在 $root\conf\nginx.conf 的 http{} 里加一行：include htglxt.conf;
& "$root\nginx.exe" -p $root -c conf/nginx.conf -t
& "$root\nginx.exe" -p $root -c conf/nginx.conf -s reload
```

Windows 开机自启（不想装服务，用任务计划即可）：

```powershell
$action  = New-ScheduledTaskAction -Execute 'C:\nginx\nginx-1.28.0\nginx.exe' -WorkingDirectory 'C:\nginx\nginx-1.28.0'
$trigger = New-ScheduledTaskTrigger -AtStartup
Register-ScheduledTask -TaskName 'nginx' -Action $action -Trigger $trigger -RunLevel Highest
```

Linux 装 nginx：`sudo apt install -y nginx`（Ubuntu）或 `sudo yum install -y nginx`（CentOS），配置放 `/etc/nginx/conf.d/htglxt.conf`，然后 `sudo nginx -t && sudo systemctl reload nginx`。

## 4. Windows 原生部署本项目（路线 B）

### 4.1 装 Node.js（≥ 18，本项目用 22 LTS 验证）

```powershell
# 方式一：官网安装包 https://nodejs.org/zh-cn/download （选 LTS，.msi 双击下一步）
# 方式二：winget
winget install OpenJS.NodeJS.LTS
node -v ; npm -v
```

### 4.2 准备数据库

已装好 MySQL（本机 5.7/8.0 均可），新建库交给迁移脚本即可，无需手工建表。

### 4.3 构建 + 初始化 + 启动

```powershell
cd <仓库路径>
npm run setup                                     # 安装前后端依赖
Copy-Item apps\server\.env.example apps\server\.env
notepad apps\server\.env                         # 改数据库账号、两个 JWT 密钥
npm run build                                     # 后端 tsc + 前端 vite build
node apps\server\dist\db\migrate.js              # 建库建表 + 权限/菜单/演示数据

# 启动后端（生产建议用 PM2 常驻）
npm install -g pm2
pm2 start docker\ecosystem.config.cjs
pm2 save ; pm2 status
```

### 4.4 前端交给 nginx

把 `docker/nginx-host.conf` 放进 nginx，并按你的实际路径改三处：

```nginx
server_name  your-domain.com;                              # 改成域名或 IP
root         <仓库路径>/apps/web/dist;                    # 改成本项目 dist 的绝对路径（用正斜杠）
location /api/   { proxy_pass http://127.0.0.1:3001; }      # 后端地址
```

### 4.5 防火墙

```powershell
New-NetFirewallRule -DisplayName 'htglxt-http' -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
# 3001 与 3306 不要对公网开放：只让本机 nginx 访问即可
```

## 5. Linux 原生部署本项目（路线 C）

```bash
# 1) Node 22
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# 2) 构建
cd /var/www/htglxt
npm run setup && cp apps/server/.env.example apps/server/.env
vi apps/server/.env            # 数据库与 JWT 密钥
npm run build
node apps/server/dist/db/migrate.js

# 3) PM2 常驻
sudo npm i -g pm2
pm2 start docker/ecosystem.config.cjs && pm2 save && pm2 startup

# 4) nginx
sudo cp docker/nginx-host.conf /etc/nginx/conf.d/htglxt.conf
sudo vi /etc/nginx/conf.d/htglxt.conf     # 改 server_name / root / proxy_pass
sudo nginx -t && sudo systemctl reload nginx

# 5) HTTPS（可选，用 certbot 自动签发）
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## 6. 本机实测记录（不是纸面推演）

环境：Windows + nginx 1.28.0（nginx.org 官方 zip）+ Node 22.23 + MySQL 5.7。

```
$ nginx -t -c conf/test-web-container.conf    # 容器版 nginx 配置
  nginx: syntax is ok / test is successful
$ nginx -t -c conf/test-web-host.conf         # 宿主机版 nginx 配置
  nginx: syntax is ok / test is successful

# 真机起 nginx(8080) + Node API(3001) + 已构建 dist，逐项探测：
[OK] 静态首页 /                      -> 200, text/html, Cache-Control: no-cache, no-store
[OK] SPA 回退 /dashboard             -> 200, 内容确认为 index.html
[OK] 静态资源 /assets/index-xxx.js   -> 200, Cache-Control: max-age=31536000,public, immutable
[OK] API 反代 POST /api/v1/auth/login -> 200, {"code":0,"message":"登录成功",...}
[OK] 未授权 /api/v1/users            -> 401（后端鉴权经代理正确透传）
$ nginx -s stop                      -> 8080 端口已释放
```

这个过程还抓出并修掉了一个真实部署陷阱（见下）。

### 已修复：容器版 nginx 启动时会解析 upstream 导致启动失败

`apps/web/nginx.conf` 原来直接写 `proxy_pass http://api:3001;`。nginx 在**加载配置时**就解析主机名，于是 `nginx -t` 直接报：

```
nginx: [emerg] host not found in upstream "api"
```

也就是说：`api` 容器还没就绪时，web 容器会启动失败。现已改为 Docker 内置 DNS + 变量延迟解析（请求时才解析，还能自动跟随容器 IP 变化）：

```nginx
resolver 127.0.0.11 valid=10s ipv6=off;   # Docker 内置 DNS
set $api_upstream http://api:3001;
location /api/ { proxy_pass $api_upstream; }
```

## 7. 排错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker compose up` 报 `JWT_ACCESS_SECRET must be set` | 生产模式禁止默认密钥 | 在 `docker/.env` 填两个 ≥16 位随机串 |
| 容器一直 `unhealthy` | mysql 首次初始化较慢 | 等 30~60 秒；`docker compose logs mysql` 看进度 |
| 打开页面 502 Bad Gateway | 后端没起来或端口不对 | `curl 127.0.0.1:3001/health`；检查 `proxy_pass` 与容器名 |
| 页面 404，刷新报 404 | nginx 缺 SPA 回退 | 确认有 `try_files $uri $uri/ /index.html;` |
| 页面能开但接口 404 | `/api` 没反代 | 检查 `location /api/` 与 `client_max_body_size` |
| nginx 报 `host not found in upstream` | 配置加载时解析主机名（容器未就绪） | 用 `resolver` + `set $var` 延迟解析（本项目已改好） |
| 上传图片 413 | nginx 体积限制 | 调大 `client_max_body_size 10m;` |
| 登录提示「尝试过于频繁」 | 触发了 10 分钟 20 次限流 | 等窗口过期，或调 `LOGIN_RATE_LIMIT` |
| `npm run build` 报 esbuild 相关错误 | 依赖没装全 | 删掉 node_modules 重新 `npm run setup` |
| 数据库连不上 | 账号/密码/端口 | `node apps/server/dist/db/migrate.js` 会打印具体错误；用 `scripts/db-report.mjs` 自检 |
| 镜像拉取超时 | Docker Hub 被墙 | 配置 `registry-mirrors`（见 1.3） |

## 8. 上线后必做

1. **改账号密码**：admin 初始密码只在演示用；个人中心 → 修改密码（会让所有会话失效）。
2. **挂定时备份**：`scripts/backup-db.ps1`（Windows 任务计划程序）或 crontab + mysqldump。
3. **接监控**：Prometheus 抓 `/metrics`（受 `METRICS_TOKEN` 保护），告警规则见 `docker/alert-rules.yml`。
4. **屏蔽内部端点**：nginx 已默认 deny `/metrics` 与 `/docs`；如需开放改配置并加白名单。
5. **验证清单**：`node scripts/db-report.mjs` 看表/索引是否齐全，跑一次 `scripts/smoke-test.ps1` 与 `node scripts/smoke-m3.mjs`。
