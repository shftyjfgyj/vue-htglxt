## 2. RBAC 设计

```
users ──< user_roles >── roles ──< role_permissions >── permissions
                                                    └─ menus.permission_code 驱动前端菜单/路由/按钮
```

- 权限码规则：`模块:动作`，如 `user:create`、`role:assignPerm`、`article:audit`；超级管理员角色持有 `*`。
- 鉴权链路：`authenticate`（校验 access token、加载用户与权限码、校验 status）→ `requirePermission('x')` → 业务。
- 前端三级：菜单由 `/api/v1/menus` 按权限过滤返回；路由 `meta.permission` 拦截；按钮 `v-permission` 移除 DOM。
- 越权实测：editor 访问 `/api/v1/users`、`/api/v1/roles`、`/api/v1/logs/operation`、给自己分配 admin 角色，均返回 403。

## 4. 与老系统的对照修复

| 老系统问题 | 新工程处理 |
| --- | --- |
| 前端调 `/api/reg`、后端只有 `/api/register`（注册 404） | 统一 `/api/v1/auth/*` 契约，Swagger 对齐 |
| 改密/改头像方法不匹配（PATCH/PUT vs POST） | 统一 REST 语义：`PUT /auth/password`、`PUT /users/:id/password` |
| 头像接口读写不存在的 `ev_users.user_pic` | 不使用该残留 schema；用户资料走 `users` 表 |
| `/tags/popular` 被 `/tags/:id` 截获 | 路由顺序与设计在 M3 按契约实现 |
| 任何登录用户可改角色（越权） | `requirePermission` + 冒烟测试断言 403 |
| 两个数据库连接池 | 单一 `pool.ts` |
| 无输入校验、无审计、无日志 | zod 校验 + operation_logs/login_logs + pino |
| Element Plus 全量引入 | 按需引入，主包 gzip 体积下降 75% |
