# 交付说明 · M11 自动审核与权限收敛（讨论结论落地）

## 1. 讨论结论（你确认的四项）

| 议题 | 结论 |
| --- | --- |
| 全站文章页给谁 | 新增权限 `article:manage`，初始给 **admin + editor**；viewer 只保留「我的文章」 |
| 无命中违禁词时 | **可信作者自动发布**，新号/有违规记录转人工 |
| 命中 block 级词 | **直接驳回并通知作者命中词**，同时记一次违规、降级信任 |
| 评论 | **复用同一引擎**自动过审（正常直接通过、命中转人工、违禁拒绝） |

## 2. 权限收敛

> **2026-10-07 修正**：本节最初的「`article:manage` 同时决定菜单与全站管理」口径有缺陷——
> editor 因此能改写/删除**他人**的文章。现已拆分为「可见范围」与「可否改写他人内容」两个判定，
> 菜单改挂 `article:audit`，`article:manage` 收归 admin。详见
> [交付说明-M13-文章越权修复.md](./交付说明-M13-文章越权修复.md)。

- 新权限：`article:manage`（**改写/删除他人文章**，仅 admin）、`sensitive:*`（词库，仅 admin）
- 菜单：`文章管理` → 改名 **全站文章**，权限由 `article:list` 改为 **`article:audit`**（admin + editor 可见，viewer 不可见）；新增 **违禁词库**（系统管理下）
- 实际生效（接口实测）：
  - admin：全站文章 + 我的文章 + 违禁词库
  - editor：全站文章（可看、可审）+ 我的文章（**没有**系统管理与词库）
  - viewer：**只有我的文章**，看不到全站文章
- 服务层判定收敛到 `modules/article/article.access.ts` 一处：
  `canViewAllContent`（`article:manage` 或 `article:audit`）管列表/详情可见范围，
  `canManageOthersContent`（仅 `article:manage`）管改写他人文章。
  此前 `article.service` / `article.bulk.service` / `moderation.service` 三份口径不一致，已合并。

## 3. 违禁词库（系统管理 → 违禁词库）

- 数据表 `sensitive_words`：词 / 分类 / 级别(`block`|`review`|`replace`) / 启用 / 备注 / **命中次数** / 创建人
- 管理能力：增删改查、启用停用、**批量导入**（一行一个词，支持「词,分类,级别」，自动跳过重复）、**命中测试**（粘一段文字，现场看判定结果与命中明细，不写库）
- 权限：编辑看不到菜单，直接访问路由被拦到 403（已用 E2E 验证）
- 预置 6 个演示词，默认多为 `review` 级——**先观察误判率再升级为 block**

## 4. 自动审核引擎（`modules/moderation`）

```
提交（新建直提 / 再次提交）
  ├─ 命中 block 级 → 驳回(status=3) + 通知作者命中词 + 违规次数+1（信任立即降级）
  ├─ 命中 review 级 → 转人工(status=1)，队列里保留命中词
  └─ 无命中
        ├─ 可信作者 → 自动发布(status=2, publish_at=now) + 记录「系统自动审核通过」
        └─ 不可信   → 转人工
```

**可信判定**（`resolveTrust`）：管理员强制可信 `users.auto_audit=1` → 直接信任；否则违规记录的**冷却期 30 天**内不信任；冷却期外按「已发布文章数 ≥ 3」判定（评论只要求无违规）。阈值可用 `MODERATION_TRUST_MIN_PUBLISHED` / `MODERATION_VIOLATION_DECAY_DAYS` 调整。

**文本归一化**：去 HTML、去实体、全角转半角、统一小写，并对「压缩版」（去掉空格与 `*·-_` 等干扰符）再扫一遍——`加 微 * 信` 这类绕过写法同样能命中（已实测）。词库内存缓存 60 秒，增删改立即失效。

**审核记录**表 `audit_records`：机器判定（auto_pass / auto_reject / to_review，含命中词与级别）与人工判定（manual_pass / manual_reject，含操作人）都落库，可追溯。

**运营开关**：用户管理新增「自动审核」列与操作——设为/取消可信作者、清除违规记录（`PUT /api/v1/users/:id/trust`）。

## 5. 前端反馈改造

- 编辑器提交后按结论提示：`未命中违禁词，已自动发布上线` / `被自动驳回：命中违禁词：代开发票（违法）` / `已提交，等待人工审核`
- 阅读页评论提示：`评论已发表` / `评论已提交，等待人工审核` / `评论被自动拦截：…`

## 6. 顺带修掉的两个真 bug

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 编辑器「保存并提交审核」**绕过了自动审核** | 自动审核只挂在 `POST /articles/:id/submit`，而新建直提走的是 `POST /articles` | 抽出 `applyAutoAudit()`，新建直提与再次提交共用（已实测：新建直提违禁内容直接驳回） |
| 2 | 多次跑 E2E 后所有用例集体失败（登录限流） | 登录限流 20 次/10 分钟，被截图脚本与多次跑测打爆 | 限流阈值改为 `LOGIN_RATE_LIMIT` 可配（本机 .env 设 300，生产仍默认 20）；E2E 全局准备里复用登录态并重置 editor 违规记录 |
