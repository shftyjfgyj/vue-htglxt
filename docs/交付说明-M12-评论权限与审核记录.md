# 交付说明 · M12 评论权限收敛 + 审核记录时间线 + 机器判定列

## 1. 评论权限收敛（按你的要求）

| 页面 | 谁能看 | 能做什么 |
| --- | --- | --- |
| **全站评论**（原「评论管理」） | 仅管理员（新权限 `comment:manage`） | 审核通过/拒绝、删除、看机器判定与审核记录 |
| **我的评论**（新页面 `/content/my-comments`） | 所有登录用户 | 只看自己的评论（含待审与被拦截）、删除自己的、跳回原文并定位 |

实现要点：

- **数据层强制**：`GET /api/v1/comments` 不再无条件返回全站数据——有 `comment:manage` 才看全部，否则服务端强制加上 `user_id = 当前用户`（前端无法绕过）
- **路由层收口**：`/content/comments` 的 `meta.permission` 由 `comment:list` 改为 `comment:manage`，编辑直接访问会落到 403 页
- **删除改为归属判定**：`DELETE /api/v1/comments/:id` 不再强制要求 `comment:delete`，而是「有删除权限/管理员可删任意，否则只能删自己的」——普通用户因此能管理自己的评论
- **回收编辑的 comment:audit / comment:delete**：评论审核与删除统一归管理员（想放开只需在「角色权限」里勾回去）
- 实测：管理员看到 78 条（全站）；editor 看到 58 条且作者集合只有自己；viewer 16 条同样只有自己；editor 删自己的评论 200

## 2. 审核记录时间线

- 新接口：`GET /api/v1/articles/:id/audit-records`、`GET /api/v1/comments/:id/audit-records`（管理员可看任意内容，作者只能看自己的）
- 新组件 `AuditTimeline.vue`：按时间倒序展示「自动通过 / 自动驳回 / 转人工 / 人工通过 / 人工驳回」，带操作者类型（系统判定 / 人工审核）、备注与命中词标签
- 接入位置：编辑器顶栏「审核记录」抽屉、全站评论行内「记录」、我的评论行内「审核记录」

## 3. 机器判定列 + 审核队列提示

- 列表接口新增 `auditDecision` / `auditHitWords`（各取该内容最近一条审核记录），前端在 **全站文章**、**全站评论**、**我的评论** 三个列表里展示机器判定与命中词
- **全站文章**顶部新增审核队列提示条：「当前有 N 篇待人工审核」+「只看待审核」一键筛选（自动审核上线后，人工只需处理机器拿不准的）

## 4. 顺带修正的一处测试隐患

文章全链路用例原先依赖历史通知数据才通过：作者给自己的文章评论时，`notify()` 按设计不会给本人发通知。现在改为让管理员去评论，作者侧再断言收到通知——从「碰巧通过」变成可确定复现。
